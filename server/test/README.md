# server/test 目录说明

这里存放后端测试，但不是所有后端测试都应该放进 `architecture/`。

## 分层约定

- `architecture/`：长期契约测试，守护稳定协议、统一收口层和基础设施不变量
- `director/`：导演调度、委派边界、自动写作触发等业务护栏
- `graphrag/`：知识图谱、语义分块、项目文件收集等检索能力回归
- `story_context/`：大纲场景契约、生产上下文包、Scriptwriter 交接上下文
- `story_memory/`：StoryMemory 状态吸收、任务包、显式吸收接口、自动写作记忆回写
- `style/`：文风档案格式化、风格注入、风格相关生成路径
- 其他测试：普通功能回归、短期 bug 回归、行为验证，应放在更贴近具体模块或功能语义的位置

## 选目录原则

- 如果断言的是事件形状、状态机、注册表、一致性、回放能力或公共基建契约，优先考虑 `architecture/`
- 如果断言的是某个具体功能的行为结果，通常不放 `architecture/`
- 如果测试只是为了修一个短期问题，修完后应评估是否能下沉到更稳定的协议边界
- 如果测试名称里已经出现明确业务对象（如 StoryMemory、GraphRAG、风格、导演委派），优先放入对应业务目录，除非它真的在守护全局基础协议
