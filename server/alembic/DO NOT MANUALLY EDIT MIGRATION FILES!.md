# ⚠️ 严格禁止手动创建或修改迁移文件！⚠️

## 致所有人类开发者与 AI 助手:

**绝对不要**手动在 `versions/` 目录下创建 `.py` 迁移文件，也**绝对不要**手动修改里面已经生成的代码！

### 为什么

1. **迁移链条的脆弱性**
   Alembic 依靠 `revision` 和 `down_revision` 形成一个严格的链式树状结构。任何手动创建的文件都可能导致链条断裂、产生分叉 (Multiple Heads)、或者形成死循环。一旦链条断裂，所有用户的更新部署都会彻底崩溃。
2. **状态不一致**
   正常的迁移文件是由 `gen_migration.py` 通过严格对比代码里的 Model (`models.py`) 与数据库真实 Schema 差异生成的。手动手写会导致代码模型与数据库物理结构发生永久性的分歧，这比单纯的代码 Bug 更加致命且极难修复。
3. **安全自愈机制冲突**
   本项目配有独立的 `auto_migrate.py` 和孤儿版本自愈逻辑。随意且未经严格测试的 `ALTER Table` 语句可能会打破自愈逻辑的前提条件，让系统的安全兜底防线失效。

### 正确的工作流

无论你要新增表、修改字段名、还是修改字段类型，**唯一**的正确做法是：
1. 去修改代码：`server/core/models.py` 或 `server/llm/llm_mgr/models.py`
2. 运行脚本让机器生成：`python gen_migration.py`
3. 检查控制台输出，如果没有报错，将生成的迁移文件提交至版本库。
