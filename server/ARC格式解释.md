# SparkArc 剧本格式规范说明 (.arc)

## 1. 场景与元数据定义
每个 `.arc` 文件通过标题和引导符定义场景的入口信息。

```markdown
# 直到...那世界崩塌...
@guide
重走最初相遇的上学路，陪她度过最后的余晖
@intro
落日将街道拉得极长，梧桐树影斑驳地落在青石板路上。
这里是一切开始的地方，也是这段错位时间即将终结的祭坛。
她牵着我的手，指尖冰冷且微微颤抖，那双本该充满灵动的眼睛，此刻像蒙了一层化不开的浓雾。
```
*   **`#` (Scene Title)**: 对应程序中的 `scene_id`，用于全局跳转。
*   **`@guide` (Chapter)**: 对应 UI 界面显示的任务指引。
*   **`@intro` (Introduction)**: 场景初始化描述，用于写前情提要并衔接到本场景的开始。

## 2. 叙事元素解析
剧本通过“旁白”与“对话”交替推动逻辑。

```markdown
[-1]
落日将街道拉得极长，梧桐树影斑驳地落在青石板路上。
她走得很慢，每一步都像是踩在摇摇欲坠的梦境边缘。

[0]
（紧紧牵着她的手）
还记得这里吗？那边以前有个卖麦芽糖的老爷爷。

[1]
（歪着头，眼神茫然）
老爷爷……糖……甜的……
```
*   **`[-1]` (Narration)**: 对应 `.story` 中的无角色文本块，通常为叙述或环境渲染。
*   **`[数字]` (Dialogue)**: 
    *   `[0]` 代表玩家/主角（根据 `chr.bind` 映射）。
    *   `[1]` 代表少女。
    *   **动作描写**: 推荐直接在旁白中描写动作，避免在对话中使用括号。

## 3. 交互逻辑（分支嵌套）
这是 `.arc` 格式的核心，采用 XML 风格确保解析器能准确识别逻辑树。

```xml
<choice>
  <opt text="指着远处的校门口">
    [0]
    你看，那是我们第一次见面的地方。
  
    [1]
    卷子……白色的……漫天都是……像雪一样。
  </opt>

  <opt text="保持沉默，只是陪她走">
    [-1]
    我没有说话，这种沉默里藏着某种即将破碎的宁静。
  </opt>
</choice>
```
*   **`<choice>`**: 开启一个交互节点。
*   **`<opt text="...">`**: 
    *   `text` 属性是玩家在屏幕上看到的按钮文字。
    *   标签内部包裹的是选择该项后触发的后续剧情。

## 4. 情感爆发点的复杂逻辑处理
在关键节点，剧本支持多层嵌套，以处理极其细腻的情绪反馈。

```xml
[1]
这是谁呀？长得真好看。

<choice>
  <opt text="试图抹去眼泪微笑">
    [0]
    对……她叫希希。她是世界上最漂亮的女孩。
    @next 最后的告别
  </opt>

  <opt text="彻底崩溃，跪在她身边">
    [-1]
    我再也支撑不住那副名为“坚强”的躯壳，膝盖重重地砸在湿冷的地面上。
  
    [1]
    哎呀，你怎么哭了？是不是哪里疼？
    @next 终局_悲剧
  </opt>
</choice>
```
*   **`@next`**: 定义该分支结束后的跳转目标。如果缺失，默认进入下一物理行。

## 5. 开发者数据映射表

| .arc 语法 | 数据类型 | 对应 `.story` JSON 逻辑 | 备注 |
| :--- | :--- | :--- | :--- |
| `[1]` | `CharacterID` | `"chr": 1` | 少女（希希） |
| `[-1]` | `Narration` | `"chr": -1` | 不显示角色名和立绘 |
| `<opt>` | `Branch` | `"optn": [...]` | 每一个 opt 对应一个逻辑分支 |

---

### 角色 ID 绑定示例 (`chr.bind`)
```json
{
  "0": "我 (玩家)",
  "1": "少女 (希希)",
  "-1": "旁白"
}
```

**解析器提示：**
1.  **自动去噪**：解析时应自动忽略 `<thought>` 标签内的内容。
2.  **上下文关联**：连续的 `[数字]` 对话块应视为同一个对话序列。
3.  **唯一标准**：旁白统一使用 `[-1]` 标记。
