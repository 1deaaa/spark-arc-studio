# ArcPen：SparkArc Scriptwriter 专属模型后训练调研与实验方案

> 调研日期：2026-08-21  
> 项目事实快照：`af109a40f563c978a806d579edce7ef38fb5f18a`  
> 目标基座：Qwen3.5-9B；验证成功后迁移到 Qwen3.5-27B  
> 训练框架：最新版 Unsloth；部署目标：GGUF Q4 级别量化

## 0. 执行摘要

### 0.1 最重要的结论

1. **不要用 4-bit QLoRA 训练 Qwen3.5。**截至调研日，Unsloth 官方明确警告：Qwen3.5 无论 dense 还是 MoE，4-bit QLoRA 都因量化差异偏大而不被推荐。ArcPen v1 应以 **BF16/16-bit LoRA 训练，合并后再导出 Q4_K_M**。用户所说的“9B Q4”应被解释为部署形态，而不是训练形态。
2. **先做 SFT，再按证据决定是否做偏好优化或在线 RL。**Scriptwriter 的主要困难中，格式、工具调用、证据边界、长度分桶和大部分文风行为都可由高质量 SFT 学会。创意写作的奖励主观且容易被长度、华丽辞藻和模板化结构欺骗，未经 SFT 基线和可靠评测就直接做 GRPO，产生奖励投机的概率很高。
3. **SFT 后的第一升级项应是长度匹配的成对偏好优化，而非直接在线 RL。**建议先做 DPO，并把 SimPO 作为长度偏差消融组。只有在 SFT+DPO 后仍存在稳定的长程缺陷，且奖励模型在人类盲评上的成对准确率达到门槛，才进入小规模 GRPO/GSPO 试验。
4. **ArcPen 不是“文学续写模型”，而是 SparkArc Scriptwriter harness 的策略模型。**训练必须同时覆盖 ARC/小说双格式、三模态、PreWrite、只读补查、工具顺序、局部 Patch、StoryMemory/GraphRAG 证据边界、长度软目标和真实保存回执。
5. **论文的核心实验应是 2×2 因子设计。**比较通用 Qwen 与 ArcPen，在最小 harness 与完整 SparkArc harness 中的表现，并计算交互效应。这样才能实证“harness + model 的 1+1>2”，而不是只报告微调模型比基座高几分。
6. **9B 阶段的合成规模建议为 13,000 个候选，严格验收 10,000 个 SFT 样本。**另外冻结 800 个评测任务；偏好阶段再从真实 SFT 模型的 on-policy 输出中构造 2,400 个高置信偏好对。不要用教师离线写出的“坏答案”替代学生真实错误。
7. **ArcPen v1 默认关闭 thinking。**SparkArc 已通过 PreWrite、`<conception>`、StoryMemory 和工具循环提供外部规划结构；训练隐藏长思维链既浪费输出预算，也可能污染正文。`<conception>` 只保存最终设计结论，不保存内部推理。

### 0.2 推荐路线

```text
冻结评测集
  -> Qwen3.5-9B BF16 与 Q4 基线
  -> 10k 高质量 harness-native SFT
  -> BF16 LoRA 合并模型评测
  -> Q4 导出与量化回归
  -> 错误归因
     -> SFT 数据缺口：补数并再训
     -> 稳定主观偏好缺口：DPO/SimPO 对照
     -> 稳定长程且 SFT/DPO 无明显收益：小规模混合奖励 GRPO/GSPO
  -> 2×2 harness/model 消融
  -> 迁移同一数据契约与评测到 27B
```

## 1. 研究问题与可证伪假设

### 1.1 研究问题

- **RQ1：**ArcPen-9B 是否在完整 SparkArc harness 中显著优于同量化的 Qwen3.5-9B？
- **RQ2：**专属模型与专属 harness 是否存在正交互，而不是两个独立增益的简单相加？
- **RQ3：**SFT 的收益主要来自文学质量、协议遵循、证据利用还是长度控制？
- **RQ4：**Q4 量化对文学质量、长上下文事实保持和工具调用分别造成多大损失？
- **RQ5：**DPO/SimPO 或在线 RL 是否能改善 SFT 后仍然稳定存在的缺陷，并且不牺牲多样性与可读性？
- **RQ6：**9B 上验证的数据配方与训练流程迁移到 27B 后，收益是否保持或扩大？

### 1.2 预注册假设

- H1：完整 harness 对通用模型和 ArcPen 都有正效应。
- H2：ArcPen 在完整 harness 中的增益大于在最小 harness 中的增益，即交互效应 `Δinteraction > 0`。
- H3：SFT 显著提高工具成功率、格式合法率、连续性和目标长度命中率；文学盲评有中等增益。
- H4：DPO 的主要增益在难以用单一参考答案监督的文风与场景完成度；若偏好对不做长度匹配，会伴随平均输出膨胀。
- H5：在线 RL 只有在高可靠、多源、长度去偏的奖励下才有净收益；单一 Critic 分数会造成奖励投机。
- H6：Q4 的工具格式损失小于长上下文细节与文学细腻度损失，因此必须逐维报告，不能只报总分。

## 2. SparkArc Scriptwriter 的真实任务契约

本节来自代码而不是自述文档。训练数据必须重现这些真实分布。

### 2.1 两种正文载体

| 模式 | 物理结构 | 正文格式 | 默认软长度 |
|---|---|---|---|
| 剧本 | 剧幕 `story_group` > 场景 `story_unit` | ARC | 精简 12-20、标准 20-35、充实 35-55 个有效叙事单元，约 ±30% 浮动 |
| 小说 | 分卷 `story_group` > 章节 `story_unit` | Markdown 小说正文 | 精简 600-1000、标准 1000-1800、充实 1800-3000 个中文字符，约 ±30% 浮动 |

若项目存在 `scene_target_chars` 或本轮显式 `target_chars`，具体目标优先，但仍是软目标。工具回执会返回 `written_chars`、目标来源和偏差；训练不能把“越接近精确字数越好”误学成机械注水。

### 2.2 三种模态不是同一种输出

1. **专有工作模式：**`system + user`，直接生成 ARC 或小说正文。固定 system 前缀，动态项目材料在 user；超预算时只裁 user 的可恢复区块。
2. **聊天模式：**`chat_system`，与用户讨论、微调或调用工具。用户没有明确要求落盘时不能默认输出完整 ARC。
3. **导演委派模式：**`pipeline_system`，受众是 Director。必须通过工具真实落盘，不能只在自然语言中声称完成。

这意味着数据集不能只有单轮 `instruction -> 文学正文`。至少要有纯正文样本、完整多轮工具轨迹、聊天协作、局部修改和冲突停止五类行为。

### 2.3 正文创作的强制状态机

```text
新写/完整重写
  -> prepare_script_creation
  -> 读取 PreWrite 确定性任务包
  -> 仅在关键证据缺失时调用只读工具
  -> create_chapter
  -> create_or_rewrite_script
  -> 检查 status=saved
  -> silent_continue 时 complete_pipeline_step

局部修改
  -> 读取已落盘正文
  -> patch_script
  -> 不要求重新 PreWrite

结构维护
  -> 跳过 PreWrite
  -> 使用重命名/重排/批量元数据工具
  -> 不调用 create_or_rewrite_script
```

`chapter_name` 与 `scene_name/work_name` 是历史兼容字段，分别指外层正文分组和内层正文文件；PreWrite 与最终落盘的名称必须完全一致。空值、`null`、自行编造编号和只输出正文不调用工具都属于任务失败。

### 2.4 ARC 内容协议

- 新建正文以唯一一个 `<conception>...</conception>` 开头；它只记录最终采用的场景功能、视角边界、连续性约束、表现策略和谨慎表达边界。
- `[旁白]` 承担动作、神态、环境和必要心理；对白行不使用括号附带动作。
- `[?]` 只表示身份尚未揭示的真实说话者，揭示后改用正式角色名。
- 旁白按表现单位拆分，不机械按句号切，也不把多个镜头、动作和心理转折塞入一个移动端长块。
- `<choice>/<opt>` 必须合法闭合；角色名只能来自允许的说话人映射。
- 输出不含外层代码围栏、解释话术、内部推理、未经授权的演出指令或不存在的资产 ID。

### 2.5 真实上下文注入

稳定项目块依次包括：故事参数、完整世界观、完整大纲、完整角色档案、说话人映射、作者风格档案。动态 user 尾部包括：

- 大纲当前场景契约；
- StoryMemory 当前场景事实包；
- 当前章最近最多 3 个场景全文；
- 前面最多 2 个章节的章末锚点；
- 梗概与节拍表组成的 narrative memory；
- 用户当前指导、Critic 修正意见、最后一行续写锚点；
- 必要时的 StoryMemory、GraphRAG、项目搜索和原文读取结果。

StoryMemory 是已保存正文的事实与证据层，不提供剧情方案；GraphRAG 是较大范围的项目事实约束；“未检索到”不能被解释为“可以自由编造”。非关键证据缺失时应采用不制造新事实的中性表达，关键证据互相冲突且任何写法都会破坏事实时才停止落盘。

### 2.6 上下文与输出预算

AgentMatchbox 默认记录 256K 上下文和 64K 单次输出上限；实际预算使用所选模型上报值。`context_budget.py` 最多预留 20K 输出 token，并另留安全余量；专有模式保护当前任务、场景事实、大纲契约和修正意见，优先裁剪世界观、大纲、角色、前文等可恢复动态材料。

训练不需要也不应该一开始就覆盖 256K。ArcPen v1 的目标是学会 harness 中信息的优先级与使用方式，而不是用极少超长样本宣称“训练了 256K”。建议训练长度课程为 8K 主体、16K 难例、32K 小比例压力样本，另用原生基座评测 64K/128K 输入退化。

## 3. 最新基座与 Unsloth 可行性

### 3.1 Qwen3.5-9B 的适配性

- 官方模型卡给出原生 262,144 token 上下文；9B 在 IFEval、MultiChallenge 和长上下文榜单上具备作为 Agent 学生模型的基础。
- Qwen3.5 是统一多模态、混合推理模型。ArcPen v1 仅使用文本路径，避免视觉编码器增加无关训练复杂度。
- 小型系列默认关闭 reasoning；这与 SparkArc 把规划外显为 PreWrite 和最终 `<conception>` 的设计相容。
- 首选 `Qwen/Qwen3.5-9B` 已后训练权重，而不是 Base。原因是 ArcPen 需要保留稳定指令遵循、工具调用和中文对话能力；Base 对照只作为小规模消融，不作为第一主线。

### 3.2 训练精度与部署精度

| 阶段 | 推荐精度 | 原因 |
|---|---|---|
| SFT/DPO/RL | BF16/16-bit LoRA | Unsloth 对 Qwen3.5 的官方推荐；避免 4-bit 训练量化差异 |
| 合并基准 | BF16 或 F16 | 测得训练方法本身的真实收益 |
| 中间质量参照 | Q8_0 | 区分普通量化损失与 Q4 特有损失 |
| 最终部署 | Q4_K_M | 与用户本地部署目标一致；必须重新跑全套 harness 回归 |

不能只在 BF16 上选出最好 checkpoint 后直接宣称 Q4 有效。每个晋级模型都必须经过 BF16、Q8、Q4 三点量化曲线。

### 3.3 初始 LoRA 配方

这是筛选起点，不是无需实验的固定答案：

- `load_in_4bit=False`，`load_in_16bit=True`，`full_finetuning=False`；
- Transformers v5，最新版 `unsloth` 与 `unsloth_zoo`；
- LoRA 目标：`q_proj/k_proj/v_proj/o_proj/gate_proj/up_proj/down_proj`；
- 筛选 `r ∈ {16, 32}`，`alpha=r`，`dropout=0`，`bias=none`；
- `use_gradient_checkpointing="unsloth"`；
- BF16，`adamw_8bit` 仅表示优化器状态压缩，不是 4-bit 模型训练；
- 学习率筛选 `{5e-5, 1e-4}`，warmup ratio 0.03，cosine decay；
- 主训练 1 epoch 起步，按 dev 曲线决定是否到 1.5 epoch，禁止默认 3 epoch；
- 只对 assistant/tool-call 目标计算损失；必须人工解码标签掩码验证 Qwen3.5 chat template；
- 长轨迹不 packing。仅短聊天子集可单独实验 packing，不能跨工具轨迹拼接；
- screening 单种子，论文最终入选配置使用 3 个训练种子，评测同时做 prompt bootstrap 置信区间。

### 3.4 序列长度课程

| 阶段 | 最大长度 | 数据 | 目的 |
|---|---:|---|---|
| A | 8,192 | 约 70% 样本 | 文学正文、格式、常见工具轨迹 |
| B | 16,384 | 约 25% 样本 | 完整项目包、连续性、多工具回合 |
| C | 32,768 | 约 5% 样本 | 大纲/角色/前文冲突、长上下文抗干扰 |

优先按非 padding token 预算控制更新量。样本被截断时，如果截掉的是最终保存回执、工具结果或正文结尾，该样本必须丢弃或重新构造，不能让模型学会半截轨迹。

## 4. SFT 数据设计

### 4.1 数量与构成

先生成 **13,000 个候选**，最终验收 **恰好 10,000 个**。若某个桶合格率不足，应补生成该桶，严禁用低质样本凑数。

| 互斥主类 | 验收数 | 关键内容 |
|---|---:|---|
| 专有模式完整正文 | 4,000 | ARC 2,400；小说 1,600；含三档长度、不同场景功能 |
| 完整 harness 工具轨迹 | 2,000 | PreWrite、按需补查、创建分组、保存、回执、静默完成 |
| 局部续写/改写/Patch | 1,000 | 唯一定位、末尾追加、保留事实、无多余 PreWrite |
| 长上下文连续性难例 | 1,000 | 干扰事实、秘密知情边界、跨章状态、显式不确定边界 |
| 长度控制专项 | 700 | 软目标、显式字符目标、短场/高潮、避免注水与硬截断 |
| 聊天协作 | 500 | 讨论、诊断、反问澄清、用户未要求时不落盘 |
| 结构维护 | 400 | 重命名、重排、批量元数据；禁止误走正文分支 |
| 冲突/不可安全写作 | 400 | 关键事实冲突、工具失败、不得伪报成功 |
| **总计** | **10,000** | 约 60% 剧本、40% 小说 |

横向标签还必须覆盖：题材、视角、场景功能、角色数、对话/旁白比、分支复杂度、风格密度、输入长度、输出长度、工具轮次、证据类型、成功/停止结局。主类互斥，但横向标签可多选。

### 4.2 长度分布必须匹配产品而非追逐超长榜单

- 小说主样本严格覆盖 600-1000、1000-1800、1800-3000 中文可见字符；每档内部均匀采样目标，不都卡在上界。
- 10% 小说样本使用用户显式目标，范围 300-5000；其中必须有“略偏离目标但完整性更好”的合格答案。
- 剧本以有效叙事单元而非字符数分桶；必须同时有对白密集、动作密集、过场和高潮。
- 只有 2% 样本允许超出产品常规长度，用于防止模型在显式长要求下过早停止；这不是 LongWriter 式 10K+ 单词训练。
- 训练、dev、test 的长度直方图分别记录；偏好对尽量长度匹配，避免把“更长”编码成“更好”。

### 4.3 数据单元

规范数据保存为结构化 `messages + tools + metadata`，训练前才用 Qwen3.5 tokenizer 的当前 chat template 渲染。禁止把 `<|im_start|>` 等模板 token 手写进数据。

每条记录至少包含：

- 唯一 ID、数据版本、prompt/tool schema 哈希、项目事实种子；
- 模态、workspace mode、任务族、难度、长度桶；
- 完整 system/user/assistant/tool 消息；
- 工具 schema 和预期状态转移；
- 可机器验证的事实约束、禁止事实、名字一致性和长度目标；
- 内容评分、协议评分、评委分歧、修改轮数；
- 教师模型、生成参数、来源许可与去重簇；
- 训练、dev 或 test split。

完整字段和合成流程见 [instruction.md](instruction.md)。

### 4.4 避免合成数据单一化

合成数据的真正风险不是“只要 AI 数据就必然崩溃”，而是递归替换真实分布、教师偏见复制和多样性塌缩。控制措施：

- 保留 Qwen 原始通用能力，不把 100% 更新都用于单一 ARC 模板；
- 用作品契约矩阵控制题材、语体、结构和角色声音，不靠提高 temperature 假装多样；
- 同一任务至少生成两个独立候选，评审时隐藏模型与长度；
- 语义去重与短语重复检测同时使用；同簇只留最强且差异真实的样本；
- 文风只使用抽象执行卡或已授权文本，不模仿在世作家的可识别风格；
- 每轮迭代都保留原始 SFT 数据，不用新模型自产数据完全替换旧数据；
- 真实用户接受/修改记录未来可作为高价值增量数据，但必须有授权、脱敏和项目隔离。

## 5. AI 文学写作常见缺陷与训练对策

学术研究与 SparkArc Critic 现有五维协议共同指向以下高频问题。

| 缺陷 | 可观察表现 | 数据与提示词对策 | 不应采用的粗暴规则 |
|---|---|---|---|
| 模板化段落 | 强主题句开头、总结句结尾、段长过度对称 | 按场景功能组织段落；允许悬置、打断和未闭合张力 | 强制随机句长 |
| 紫色散文 | 抽象华丽比喻堆叠、意象互相冲突 | 比喻必须来自视角人物可感知世界，并承担信息/情绪功能 | 禁止所有修辞 |
| 陈词滥调 | 通用“心中一震”“空气凝固”等可替换句 | 要求具体动作、物件、关系历史和现场目标支撑感受 | 维护无限黑名单 |
| 过度解释 | 对白直接说明关系、情绪、主题和动机 | 为角色设置欲望、隐瞒与风险；用行动和错位回应形成潜台词 | 机械执行“只展示不讲述” |
| 人物同声 | 角色共享句法、词汇、礼貌度与信息密度 | 做盲去名说话人归属测试；记录每人语体和回避策略 | 为每人添加口头禅 |
| 道德化收束 | 结尾总结意义、上价值或替读者解释 | 以动作、选择、代价、发现或未决问题收束 | 所有结尾都强行反转 |
| 结尾膨胀 | 临近结束扩大世界危机、连续多个结尾 | 训练场景边界，下一场动作不得提前 | 只靠截断 token |
| 情绪扁平 | 直接贴标签，缺少因果、身体和决策变化 | 情绪必须改变注意、措辞、动作或选择 | 每段堆感官描写 |
| 逻辑便利 | 为推进剧情临时添加事实、能力或巧合 | 输入 oracle 事实表；未知即中性写法，冲突则停止 | 让评委凭印象判连贯 |
| 重复与复读 | 同义反复、续写复述前文、段末重申 | 加入最后一行锚点和重复率检测；训练“从锚点后继续” | 单纯提高 repetition penalty |

核心原则是评价“表达是否服务当前作品契约”，而不是把一种现代简洁风格强加给全部题材。数据合成 Agent 的完整自检清单见 `instruction.md`。

## 6. 是否需要 RL：分级决策

### 6.1 先把问题归因

评测失败分为四类：

1. **知识/上下文缺失：**数据或 harness 问题，RL 无法修复。
2. **协议不会：**优先补 SFT 轨迹和确定性验证。
3. **偏好边界不稳定：**适合 DPO/SimPO。
4. **跨长输出的全局目标已知但 token 级 SFT 收益饱和：**可能适合在线 RL。

只有第 4 类才直接支持“需要 RL”的结论。

### 6.2 DPO/SimPO 先行条件

从当前 SFT 模型对冻结 prompt 的真实采样中，每题生成 4 个候选。由长度去偏的多评委选择，最终形成 2,400 个高置信偏好对：

- 1,400 个文学与场景完成度对；
- 400 个连续性/事实边界对；
- 300 个长度控制对；
- 300 个工具与格式恢复对。

chosen/rejected 的可见长度比优先限制在 `[0.85, 1.18]`；长度就是任务目标时单独标注。评委分歧大或两个答案都差的样本不进训练。

主实验用 DPO，初始 `beta=0.1`，并做 `{0.05, 0.1, 0.2}` 小网格；SimPO 作为参考模型内存与长度归一化消融。DPO 后若输出明显变长而长度控制分不升，视为失败而非收益。

### 6.3 在线 RL 的进入门槛

以下条件必须全部满足：

- SFT 至少两轮数据补洞后，目标缺陷提升小于预注册最小效应；
- DPO/SimPO 仍未解决同一缺陷；
- 每个训练 prompt 的 4-6 个 on-policy 候选存在可区分的质量方差；
- 写作成对奖励模型在人类盲评集上准确率 ≥75%，且长度匹配子集 ≥72%；
- 位置交换一致率 ≥90%，重复判分一致率 ≥85%；
- 奖励与长度的偏相关在控制人类质量后不显著偏高；
- BF16 SFT checkpoint、完整 eval 和回滚机制均已冻结。

### 6.4 最合适的 RL 形态

不推荐 PPO。优先做 **LoRA GRPO/GSPO 小规模试验**，借鉴 Writing-Zero 的“成对生成式奖励模型”与 LongWriter-Zero 的“长度、写作、结构分奖励归一化”，但不直接宣称复现 BRPO，因为 Unsloth/TRL 未提供同名开箱实现。

Qwen3.5 在 Unsloth 中做 GRPO 时按官方说明关闭 fast vLLM inference，使用 Unsloth inference；先限制 8K-16K 序列、每题 4 个 generation，确认稳定后再增到 6。长输出 RL 的计算量与方差都很高，只使用经过筛选的 1,200-2,000 个训练 prompt。

### 6.5 混合奖励设计

先执行硬门禁：若格式不可解析、工具 schema 错误、关键工具顺序错误、伪报保存或越过明确场景边界，总奖励直接置为 `-1`，不让华丽文字抵消协议失败。

通过门禁后，各分量先在组内标准化到 `[-1,1]` 再组合：

| 分量 | 权重起点 | 来源 |
|---|---:|---|
| 写作质量 | 0.30 | 成对 GenRM：按任务动态提出原则、比较候选、给证据 |
| 连续性与控制信号 | 0.22 | oracle 事实表 + 强评委核对；秘密知情边界单独计 |
| harness 成功 | 0.20 | 工具名、参数、顺序、真实 `status=saved`、完成控制 |
| 格式合法与纯度 | 0.13 | ARC/小说解析器、唯一 conception、无元话语 |
| 长度遵循 | 0.10 | 对 ±15% 设置平台区，超过后平滑下降；绝不按绝对长度奖励 |
| 风格契约 | 0.05 | 风格执行卡与人物声音，不比较是否像某位作家 |

额外监控而不直接高权重优化：重复率、Self-BLEU、语义多样性、平均句长、比喻密度、道德总结率、工具调用次数、KL 漂移。任何监控项快速恶化都触发早停审查。

禁止把 SparkArc Critic 的单次总等级直接当唯一 reward。Critic 可以提供特征，但其自身也可能偏好正式、完整、较长和结构对称的文本。

## 7. 评测体系

### 7.1 冻结任务集

- `dev_public`：500 题，执行 Agent 可反复使用；
- `test_blind`：300 题，只在里程碑运行，禁止用于补数；
- 其中 120 题进入三人类评委盲评核心集；
- 世界观、角色名、事实图与剧情种子按项目级分组切分，禁止同一项目跨 train/test；
- 用 MinHash、最长公共短语和 embedding 三重查重，保存污染报告。

### 7.2 指标分层

**确定性指标：**

- ARC/小说解析成功率；
- `<conception>` 唯一与位置合法率；
- 说话人合法率、标签闭合率、无括号动作率；
- 工具 schema、顺序、名字一致率、保存成功率；
- 关键事实支持率、矛盾率、未知事实擅自确定率；
- 长度档命中率、显式目标偏差、截断率、复读率；
- 多场任务板更新准确率。

**文学指标：**

- 场景功能完成度；
- 因果与长程连贯；
- 人物选择可信度和声音可区分度；
- 潜台词与信息控制；
- 具体性、修辞功能、节奏；
- 风格契约一致性；
- 结尾完整但不总结、不越界；
- 新颖性与跨样本多样性。

**系统指标：**

- 每个成功正文的模型请求数、工具调用数、失败重试数；
- prompt/completion/cached token；
- TTFT、总时延、字符/秒、p50/p95；
- 峰值 VRAM/RAM、Q4 文件大小；
- 每个被人类接受正文的成本。

### 7.3 评委去偏

- 成对盲评同时交换 A/B 位置；
- 内容评分时隐藏模型、量化、token 数和训练阶段；
- 长度相差大时先做长度匹配子集，再报告原始与 length-controlled 两套结果；
- 不让合成教师成为唯一评委，至少使用两个异源强评委和一个规则/项目 Critic；
- 10% 样本重复判分，报告一致率；
- LLM 分数只做规模化代理，最终核心结论使用人类盲评；
- 报告 Krippendorff's alpha 或成对一致性，而不是只报平均分。

### 7.4 2×2 “harness + model”实验

| | 最小 harness H0 | 完整 SparkArc harness H1 |
|---|---|---|
| 通用模型 M0 | 平铺项目摘要、原始工具，无 PreWrite/StoryMemory 状态机 | 当前 SparkArc 全链路 |
| ArcPen M1 | 与 M0 相同的 H0 | ArcPen + 当前 SparkArc 全链路 |

交互效应：

`Δinteraction = Score(M1,H1) - Score(M1,H0) - Score(M0,H1) + Score(M0,H0)`

H0 仍需具备安全沙箱与同样的最终文件验证，不能故意做成不可用基线。分别在 BF16 与 Q4 上运行。主结果用混合效应模型或分层 bootstrap，任务为随机效应，模型、harness、交互项为固定效应。

### 7.5 晋级门槛

SFT v1 进入偏好阶段前，至少满足：

- 保存成功率 ≥95%；ARC/小说可解析率 ≥99%；
- 关键事实矛盾率较 Q4 基线下降 ≥40%；
- 长度软目标命中率 ≥85%，截断率 ≤1%；
- 人类盲评对 Q4 基线胜率下界（95% CI）>50%；
- 通用 IFEval/基础对话护栏相对下降不超过 3 个百分点；
- Q4 相对 BF16 的文学盲评胜率损失不超过 8 个百分点。

若达不到，先回到错误桶补数据，不进入 RL。

## 8. 9B 到 27B 的迁移

9B 阶段的真正产物应是可迁移的 **数据契约、评测集、奖励校准集与 harness 消融方法**，而不仅是一个 adapter。

迁移步骤：

1. 固定 9B 已通过的数据版本与评测版本，不重新让 27B 教师改写全部数据；
2. 在 27B 上做 500 条、2,000 条、全量三点数据规模曲线，检查是否更少数据即可饱和；
3. 使用同一 BF16 LoRA 主线，不把 9B adapter 权重直接移植；
4. 重新筛 LoRA rank 与学习率，不能假设 9B 最优超参可迁移；
5. 27B 更强的指令遵循可能降低工具 SFT 需求，但文学偏好与长程一致性仍须实测；
6. 同样导出 Q8/Q4 并运行量化回归；
7. 用相同 2×2 设计比较交互效应是否随模型规模变化。

## 9. 论文与工程产出建议

建议论文主线题目：**《面向长篇叙事创作的垂直 Agent Harness 与专属小模型协同后训练：ArcPen/SparkArc 的设计与实证》**。

可发表的贡献应落在：

1. 从真实创作工程抽象出的 harness-native Scriptwriter 数据契约；
2. 同时测量文学质量与端到端落盘成功的双层评测；
3. 2×2 设计对 harness/model 正交互的实证；
4. BF16 后训练到 Q4 部署的量化损失曲线；
5. SFT、偏好优化、可选 RL 的分阶段消融；
6. 9B 到 27B 的可迁移性。

不要把以下内容当论文主结论：单次漂亮案例、训练 loss、一个 LLM judge 的高分、无基线的 Q4 演示、或把应用系统模块数量当创新。

## 10. 风险清单

- **最高风险：**把 Q4 部署目标误作 4-bit QLoRA 训练。
- **高风险：**训练数据只含最终正文，破坏工具和 PreWrite 行为。
- **高风险：**同一教师生成、评审并修订全部数据，形成同源偏差。
- **高风险：**DPO/RL 偏好更长、更华丽答案，文学分数虚高。
- **高风险：**训练/评测按单个场景随机切分，导致同项目事实泄漏。
- **中风险：**过度训练 ARC 格式造成小说、聊天和通用能力退化。
- **中风险：**长序列被静默截断，模型学会不保存或不收束。
- **中风险：**把 Critic 的 AI 味规则固化成词汇黑名单，导致新模板。
- **中风险：**只报告 BF16，忽略 Q4 实际部署退化。
- **合规风险：**使用未授权小说或模仿在世作者形成版权与人格风格争议。
